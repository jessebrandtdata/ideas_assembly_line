# Bill Delay Tracker prototype

See [`../prototype-bill-delay-tracker.md`](../prototype-bill-delay-tracker.md) for what this is and how to run it.

`collect.py` → `data/*.csv` (versions, pages, ingest dates, summaries) → `delays.py` → `data/stats.json` + `data/delays.json` (+ `data/delays.js`, the same document as a script) → `dashboard/`.
Lag runs from the day GovInfo took a text version in (its MODS `dateIngested`, in `ingest.csv`; the date printed on the bill rides along as `printed_date`) to the date the Congress.gov API says the summary was last updated (`lastSummaryUpdateDate`). CRS writes summaries for introduced versions only in the 119th Congress, so the page opens on the introduced stage and labels the later stages as CRS exceptions.
`tests/fixture/` runs `delays.py` on a bundled sample with no network.
`dashboard/index.html` is the view of the data. Open it straight from disk, no server needed: browsers block `fetch()` of local files on `file://` pages, so `delays.py` also writes the data as a script, `data/delays.js`, and the page loads it with a plain `<script>` tag (the d3 library and the webfont still come from the network). Serving the prototype folder (`python3 -m http.server`, open `/dashboard/`) works too. Page-wide filters sit in the top row: stage (default introduced; the other stages name themselves CRS exceptions and show a notice quoting the Congress.gov help page), bill type, a text-posted from/to date range (two day-level date pickers bounded by the first and last text date in the data; empty = open side; inclusive, on the day the version appeared on GovInfo) and a "Clear date filters" button; a monthly stacked-share chart (summarized vs waiting, by month the text was issued; no lag-over-time lines, which right-censoring would make misleading) shades the months the range touches; beneath the histogram are its own controls, a bin-width slider (7 to 90 days) and a checkbox to include bills without a summary ("still waiting" at the introduced stage; at a later stage the bar reads "no summary", because none is coming). The stage select also scopes the "pages of bill text" card and both lines of the cumulative pages chart to that stage's text versions (all stages: every edition, including unmapped ones); the "reported by committee" card ignores it. Two top-10 tables close the page, both following the page filters and ties broken by bill number: "Longest lags" (summarized records, by lag in days) and "Oldest bills still waiting" (introduced stage: records with no summary, by days from the posting date to the data's as-of date; under All stages, the introduced version of each bill with no summary at any stage; at a later stage the heading reads "Oldest without a …-stage summary"); each bill is a link to its congress.gov page.

## Exports

Each of the four charts has "Download PNG" and "Download SVG" buttons above it, and each of the two tables has a "Download CSV" button in its heading. The files follow the current stage, bill type and date filters and are named `bill-delay-<figure>-<stage>-<type>[-<from>_<to>]-<as_of>`, for example `bill-delay-histogram-all-all-2026-10-15.png`. The PNG is a fixed-size export: twice the chart's design size (the 920 px wide viewBox plus the title band), the same file whatever the window width. Because an SVG loaded as an image cannot fetch the Google webfont, PNGs use the system fallback font. The CSVs hold every row of the filtered table in its sort order, not only the ten shown (longest lags: all summarized text versions; oldest waiting: all records the table ranks), with both the GovInfo posting date (`text_date`) and the date printed on the bill (`printed_date`).
